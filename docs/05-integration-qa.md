**איך הייחוס (`volume-solid-01`) משמר:** כל קפיצה מוסיפה `window.location.search` — `'../' + dest + '/index.html' + window.location.search` — בכל אתרי היציאה, ב-Back (`goBackToPrevPart` עם `location.replace`), בהפניית ה-root, ובקפיצת ה-Resume של ה-loader. `?resetState` מסיר את עצמו מה-URL (`history.replaceState`) כדי לא להתגלגל הלאה.

**האם התיקון תלוי בניתוב הפלטפורמה — כן:**
- אם **הלומדה מנתבת פנימית** עם registration אחד (מודל הייחוס) — התיקון **חובה**, אחרת כל רכיב אחרי 01 נפתח בלי LRS ובלי מסמך מצב.
- אם **הפלטפורמה משיקה כל רכיב ב-URL משלו** (מודל הסקיל / `percent-02`) — הפלטפורמה מספקת את הפרמטרים בעצמה, הניווט הפנימי הוא dev-only, והתיקון רלוונטי רק לבדיקות פנימיות.

**הצעת תיקון ממוקדת (לא מומשה — ממתינה להכרעה על בעלות Resume/ניתוב):** בכל 13 האתרים בלבד, ללא שינוי לוגיקה:
```js
window.location.href = '../' + dest + '/index.html' + window.location.search;            // קדימה
window.location.href = '../' + prev + '/index.html' + window.location.search + '#last';  // אחורה
```
ה-hash אחרי ה-search (כך `#last` נשמר). שאלה פתוחה: `location.replace` ב-Back (כמו בייחוס, פותר גם חלק מ-I-2) — תלוי באותה הכרעה. בדיקות אחרי תיקון: הפרמטרים שורדים את כל 6 המסלולים ואת כל ה-Back; `#last` ממשיך לנחות במסך האחרון; פתיחה בלי פרמטרים לא נשברת.
